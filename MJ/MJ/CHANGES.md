# Change Report

## Canonical path

- `main.py` now starts `tony.py`.
- The former active `agent.py` implementation was moved to `core/runtime_agent.py`.
- `core/agent.py` exports the runtime entrypoint.
- The former active `prompts.py` implementation was moved to `core/prompts.py`.
- `prompts_mj.py` was removed as a duplicate; the already-Tony prompt content was retained as the canonical prompt module.

## Deleted files

The following files were unreachable from the active `main.py` -> `tony.py` path and were removed as duplicate or scratch implementations:

- `Mj_agent.py`: duplicate agent implementation.
- `Nova_Voice_Assistant.py`: parallel legacy voice assistant.
- `nova_gui.py`: parallel legacy GUI.
- `nova_gui.spec`: obsolete build spec.
- `Nova 2.0.spec`, `Nova 3.0.spec`, `Nova 4.0.spec`: obsolete duplicate build specs.
- `memory_db.py`, `nova_db.py`, `memory_models.py`: duplicate memory implementations not imported by the active path.
- `animation.py`, `updated_Animation.py`: standalone animation implementations not wired into the current UI.
- `bridge.py`, `c.py`, `ch.py`, `testing.py`, `ytb_code.py`, `llava_server.py`: experimental or scratch scripts not imported by the active entrypoint.
- `__pycache__/` trees and generated bytecode: runtime-generated artifacts.

## Security changes

- `serviceAccount.json` and `.env` are absent from the repository.
- Hardcoded Groq, YouTube, and Gmail credentials were removed from `Tools/` and `tools.py`.
- Credential lookups now use environment variables.
- `.env.example` documents the required configuration, and `.env` is ignored.

Authentication and Firebase behavior that requires a real credential is intentionally not fabricated. Supply `FIREBASE_SERVICE_ACCOUNT_JSON` or `GOOGLE_APPLICATION_CREDENTIALS` before using those capabilities.

## Identity changes

- Live runtime modules and prompts use Tony.
- Remaining user-facing Nova labels in code tools and system-power messages were changed to Tony.
- `NOVA_VARIANT` was changed to `TONY_VARIANT`.
- The LiveKit subdomain in `livekit.toml` was not changed because it is an external deployment identifier, not a branding string. Renaming it without the matching LiveKit deployment would break connectivity.

## Latency audit

- Direct command routing remains before the model fallback in `core/runtime_agent.py`, so simple commands do not require an unnecessary second model call.
- Desktop process polling and blocking SAPI speech are executed through async executors/background tasks in the existing runtime path.
- Duplicate agent implementations and duplicate startup paths were removed, preventing redundant model or connection initialization.
- Heavy action libraries remain isolated in action modules; no speculative rewrite of tool behavior was made.

## Validation

- The canonical modules compile with Python 3.12.
- `import livekit.agents` succeeds in the project virtual environment.
- `import main` succeeds when the required LiveKit submodule is available.
- Source-only scans contain no remaining standalone `MJ`, `mj`, `Nova`, or `nova` identity tokens except the preserved external LiveKit subdomain noted above.

## Needs confirmation

- The LiveKit project subdomain `nova-iezs0u48` should only be changed after a replacement LiveKit deployment is supplied.
- Firebase/voice-authentication behavior cannot be end-to-end verified without valid credentials and local enrollment data.
- A full voice round-trip requires network access and live API credentials; source import and compilation do not prove that external service round-trips succeed.
